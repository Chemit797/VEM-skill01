# 细胞 × 基因表达矩阵预测：维护实验历史

先找当前项目的 `research/t1_matrix_history/history.jsonl`；独立分发仓库或用安装器初始化的项目可用 `catalog/history.jsonl`。同时存在时用前者。读旁边的 `DIRECTIONS.md` 看方向，按记录 ID 查 JSONL 看具体证据。版本和分数属于项目，不写回这个 skill。

**首次建盘。** 先读项目的登记索引和字段说明，逐条清点提交与候选，再追到有明确关系的生成清单、源代码、原回执和本地开发报告。除获胜路线外，也覆盖早期、降分、失败、未提交、重复上传、暂时不能定位的记录。核对任务/时期、指标尺度、父件、文件身份。使用项目数据命名目录；不把发布的验证真值或隔离诊断带入正式方向清单。没有数据时可先建立空 JSONL 并加入有证据的首批记录，不能从示例捏造本项目成绩。

**记事实。** 一句话说清“在什么底稿上，对哪些细胞或基因，实际改了什么”；把父子总分和四项逐一相减。一个模块一起加入所得的差，只记给整步；不同底稿的旋钮不能拼成一条剂量曲线。没有单项消融，就保留该方向和整件成绩，差值留空。官网显示、本地重新评分、外部回放分开；不同口径或不同窗口的总分不相减。一次上传对应一个事件；同 SHA 再次上传不算独立复现。没有分、未执行、生成失败、与父件矩阵相同是四件不同的事；后者要有实际比较证据，不能凭同分推断。

**批后更新。** 用 [明细格式与追加示例](references/ledger.md) 生成一个小批次，运行此 skill 的 `scripts/history.py append`，再用 `check` 对账。输出由同一份明细生成。已经有一条相同 ID 时先查是否早就收过；不同来源的冲突并列保留，不覆盖原件。涨跌持平和无可比分数同表展示，不给路线设禁用名单。

**给 agent 留实际选择权。** 在已获授权的实验批次里，安排已知方向的延伸，也留实际运行机会给 agent 自主提出的清单外方法。不限配额；资源仅够串行时，把两种尝试排入同批先后执行，未执行的如实记。新问题只需讲清改什么、和谁比；不要求先证明为何一定会赢。真正的新方向直接追加，不必归入现有分类。用户只要求复盘、建表或提计划时，在相应范围交付；本 skill 不自行训练、打分、上传、定时运行或向团队发消息。
